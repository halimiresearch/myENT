# Audit 001 — myENT (Jurnalistik App)

Tanggal: 2026-10-18
Mode: antislop AFTER (audit project yang sudah jadi)
Scope: seluruh repo (apps/api, apps/admin, apps/mobile, infra, docs)
Status: **menunggu pemilihan nomor** — belum ada kode yang diubah. Nomor yang tidak disebut tidak disentuh.

Metode: 3 audit paralel per area + verifikasi ulang manual oleh auditor untuk temuan
berdampak (form mati, bug konstanta waktu, authz, kontras warna dihitung presisi
oklch→sRGB dengan rumus WCAG).

Prioritas mengikuti tier aturan antislop: **Hard Gate = HIGH, Purpose-Gate = MEDIUM,
Quality Locks = LOW**. Section B adalah temuan engineering di luar cakupan antislop
(permintaan user: analisa keseluruhan sebagai senior fullstack), prioritasnya
penilaian auditor.

## A. Temuan antislop (sitasi R-XX)

### A-01 — HIGH — R-26 (+C-2)
**12 form di web admin tombol submit-nya mati saat diklik.**
Alasan satu baris: elemen interaktif tanpa perilaku nyata = dead control (Hard Gate).

Bukti (terverifikasi manual):
- `apps/admin/lib/ui.tsx:100` — `Btn` selalu `<button type="button" ...>`; tidak pernah `type="submit"`.
- Form punya `onSubmit` tapi tombolnya tidak memanggilnya:
  - `apps/admin/app/meetings/page.tsx:64,68` (Buat DRAFT)
  - `apps/admin/app/meetings/[id]/page.tsx:122,126` (Simpan lokasi) dan `192,198` (Sesuaikan)
  - `apps/admin/app/members/page.tsx:98,106` (Tambah)
  - `apps/admin/app/assignments/page.tsx:67,71` (Buat)
  - `apps/admin/app/announcements/page.tsx:35,42` (Kirim broadcast)
  - `apps/admin/app/inventory/page.tsx:65,69` (Tambah) dan `122,127` (Kirim return)
  - `apps/admin/app/duty/page.tsx:32,37` (Generate roster)
  - `apps/admin/app/profile/page.tsx:43,46` (Ganti password) dan `52-67` (Mulai setup 2FA)
  - `apps/admin/app/config/page.tsx:47,52` (Simpan) — klik mati; Enter jalan (1 field)
- Form multi-field (`>1` input) juga tidak bisa di-submit via Enter: implicit submission
  hanya jalan tanpa submit button bila form punya tepat 1 field (HTML spec). Jadi
  meetings/members/announcements/duty/assignments/inventory-add/dll benar-benar
  tidak bisa disubmit lewat UI.
- Login & reset aman (memakai `<button>` native submit).

Catatan verifikasi: dicek lewat pembacaan kode; R-35 (click-through browser)
dijalankan pada tahap perbaikan.
Saran fix: beri `Btn` prop `type` (default `submit` saat di dalam form) atau pasang
`onClick={() => form.requestSubmit()}` — root cause-nya satu tempat.

### A-02 — HIGH — R-25
**Kontras teks di web admin gagal WCAG AA.**
Alasan satu baris: teks abu `gray-400` dipakai sebagai teks utama di 26 tempat = 2,6:1.

Angka terhitung (oklch Tailwind v4 → sRGB, rumus kontras WCAG):
- `text-gray-400` (#99a1af): **2,6:1** di atas putih, **2,35:1** di atas canvas #f2f3f9.
  Minimum AA teks normal 4,5:1. Dipakai untuk: Empty state 14px (`ui.tsx:157`),
  header tabel 12px (`ui.tsx:123`), sub Stat 12px (`ui.tsx:31`), NIM/email 12px
  (members, dashboard, analytics, meetings/[id], inventory, audit-logs),
  label grup sidebar 11px (`shell.tsx:133`), label "Admin Panel"/"UKM Jurnalistik"
  11px, placeholder input, label Loading.
- Subjudul PageHeader `text-gray-500` di atas canvas: **4,37:1** (marginal, < 4,5).
- Chip peringkat poin `text-yellow-700` di `gold-100`: **4,44:1** (marginal; 12px bold
  bukan "large text").
- Lulus: teks brand 8,49–10,19:1; chip mobile ok/warn/bad 4,56/4,58/5,51:1.

### A-03 — HIGH — R-27
**Loading state hilang di 9 halaman admin; beberapa kegagalan error senyap.**
Alasan satu baris: UI data tanpa state loading menampilkan "Belum ada data" yang menyesatkan saat memuat.

- Ada `<Loading>`: hanya `assignments`, `audit-logs`, `materials`. Dashboard punya
  skeleton sendiri (`page.tsx:51-58`). Analitik memakai teks "Memuat…" polos.
- Tanpa loading state apa pun: `meetings`, `meetings/[id]`, `members`, `recap`,
  `config`, `announcements`, `inventory`, `duty`, `profile` → first paint = tabel
  kosong / "Belum ada data".
- Error senyap: `analytics/page.tsx:98` `Points()` tanpa `.catch` → gagal = tampil
  Empty selamanya (tidak ada error state); riwayat inventaris tanpa catch;
  QR di `meetings/[id]:24` `catch(() => {})`.
- Empty & error state sendiri sudah tersedia (`Empty`, `Err`) dan dipakai di hampir semua halaman.

### A-04 — HIGH — R-32
**Drawer menu admin tidak bisa ditutup dengan Escape dan tanpa focus trap.**
Alasan satu baris: dialog/overlay wajib bisa ditutup dengan Escape dan dinavigasi dengan keyboard.
- `apps/admin/app/shell.tsx:177-184` — drawer hanya tertutup via klik overlay;
  tidak ada handler Escape, tidak ada focus trap. Fokus keyboard tetap bisa
  "keluar" ke konten di belakang overlay.

### A-05 — HIGH — R-02
**Karakter em dash (—) dipakai di teks yang dilihat pengguna.**
Alasan satu baris: R-02 melarang em dash di semua teks; pakai koma/titik/titik dua.

- Admin: `app/page.tsx:91` ("Perlu Perhatian — Sering Alpha"), `meetings/[id]:114`
  dan `:141` (nama — alasan), `members:69` ("... ok — lihat konsol"),
  `duty:39`, `reset:46`.
- Mobile: `presensi_page.dart:58,61,64`, `tugas_page.dart:51`.
- API yang tampil di PDF/user: `apps/api/src/common/recap-pdf.ts:28`
  (`${date} — ${title} — ${status}` di PDF rekap).

### A-06 — LOW — R-21
**Tidak ada dark mode / toggle, dan tidak ada alasan tertulis untuk tema tetap.**
Alasan satu baris: R-21 meminta toggle bila tidak ada alasan kuat untuk tema fixed;
untuk tool internal tema terang itu pilihan yang sah — tapi harus diputuskan dan
dicatat (R-31), bukan default senyap. Grep `dark:` / `prefers-color-scheme` = 0 hit di admin.

### Catatan yang sudah bagus (tidak perlu diubah)
- Tidak ada gradient biru-ungu, glow, glassmorphism berlebih (hanya 1 backdrop-blur
  header, dalam batas R-10), background grid, atau bento (R-01, R-07, R-10, R-13).
- Ikon admin digambar tangan (inline SVG) dan relevan per menu (kalender untuk
  Kegiatan, jam untuk Piket, dst) — bukan ikon library generik (R-04).
- Semua item navbar menuju route yang benar-benar ada (R-24); CTA spesifik
  ("Buat DRAFT", "Generate roster") bukan "Get Started" (R-15); tanpa buzzword (R-16).
- Tanpa testimoni/statistik palsu — semua angka dari API nyata (R-17, R-18, R-36);
  avatar inisial, bukan foto orang (R-23).
- Identitas visual nyata: navy #134179 + gold #F4CB01 + monogram ENT, konsisten
  admin ↔ mobile (R-20); tipografi Plus Jakarta Sans punya alasan brand (R-06).
- Tidak ada patch script yang menulis ulang CSS (R-33).

## B. Temuan engineering (di luar cakupan antislop)

### B-01 — HIGH — Authorization tidak konsisten (4 lubang terverifikasi)
Aturan proyek sendiri (AGENTS §6 + `common/policy.ts`) mewajibkan scope divisi,
tapi 4 endpoint melewatinya:
1. `apps/api/src/assignments/assignments.service.ts:149-160` — `review` tidak
   memakai `canManageMember`/`divisionScope`; OFFICER bisa review submission
   divisi lain. Bandingkan `fileUrl` (`:165-172`) yang sudah di-scope.
2. `apps/api/src/users/users.controller.ts:193-199` — import CSV menulis `division`
   dari file bebas; OFFICER bisa menyuntik anggota ke divisi lain. `create` (`:68`)
   membatasi ke divisi aktor.
3. `apps/api/src/attendance/attendance.service.ts:115` — `adjust` mengizinkan
   self-adjust (`actor.id !== target.id` tidak wajib); officer bisa mengubah
   status dirinya sendiri kapan saja, termasuk setelah finalize. Bandingkan
   `absence.decide` (`absence.service.ts:112`) yang melarang keputusan untuk diri sendiri.
4. `apps/api/src/loans/loan.service.ts:121-149` — `returnLoan` tanpa scope:
   semua OFFICER/ADMIN bisa menutup pinjaman siapa pun; `cancel` (`:151+`)
   hanya peminjam.
Dampak: kebijakan scope divisi dapat dilewati siapapun ber-role OFFICER.
Tidak ada test yang menutupi keempatnya.

### B-02 — HIGH — Bug konstanta waktu `60_1000` (bukan `60_000`) di 3 tempat
Pola `5 * 60_1000` = 5 × 601.000 ms ≈ 50 menit, bukan 5 menit.
1. `apps/api/src/auth/auth.service.ts:84` — challenge 2FA hidup ≈50 menit
   (komentar + `docs/API.md` bilang 5 menit).
2. `apps/api/src/meetings/meetings.service.ts:177` — token QR hidup ≈50 menit
   (komentar bilang 5 menit; mobile `qr_scan_page.dart:4` juga bilang 5 menit).
3. `apps/api/src/meetings/meetings.service.ts:262` — window reminder penutupan
   ≈5 jam, niatnya 30 menit.
Dampak: jendela token 10× lebih lama dari desain (relevan security untuk QR/2FA).

### B-03 — HIGH — Piket: jam default diinterpretasikan UTC, PRD bilang WIB
`apps/api/src/duty/duty.service.ts:14-19` memakai `setUTCHours` untuk `'06:00'`/`'22:00'`.
PRD §(waktu): "Input waktu kegiatan oleh pengurus diinterpretasikan sebagai WIB dan
dikonversi di backend" (`docs/PRD.md:150-151`). Hasil nyata: window piket default
buka **13:00 WIB**, tutup **05:00 WIB** — bukan 06:00–22:00. Form admin tidak
mengirim `openTime`/`closeTime` (selalu default). Juga tidak ada validasi open<close:
pasangan salah → CHECK constraint DB → 500.
Catatan: `apps/api/src/meetings/meetings.service.ts` untuk meeting biasa menerima
waktu dari form (datetime-local) jadi tidak terkena; yang bermasalah jalur duty.

### B-04 — MEDIUM — Push FCM mati di produksi sesuai konfigurasi yang dikirim
`apps/api/src/notifications/notifications.service.ts:60` butuh `FCM_PROJECT_ID`
**dan** `GOOGLE_APPLICATION_CREDENTIALS`; `docker-compose.prod.yml` hanya mengisi
`FCM_PROJECT_ID` (`:47`). Halaman Pengumuman menjanjikan "Broadcast push ke
anggota via FCM" — di prod push tidak akan terkirim, hanya notif in-app
(yang memang di-desain sebagai sumber kebenaran, tapi UI-nya tidak mengatakan itu).

### B-05 — MEDIUM — Pool Prisma dibuat sebelum `.env` terbaca
`apps/api/src/prisma/prisma.service.ts:7-8` — `new Pool({ connectionString: process.env.DATABASE_URL })`
jalan saat import modul; `ConfigModule.forRoot()` (yang memuat `.env`) baru jalan
setelahnya, dan `main.ts` tidak memuat dotenv lebih dulu. Di Docker/CI (env nyata)
aman; dev lokal yang hanya mengandalkan `.env` bisa membangun pool dengan URL salah.

### B-06 — MEDIUM — Beberapa input wajar menghasilkan 500
- `auth.service.ts:152` — reset password ke userId tak dikenal: `findUniqueOrThrow` → 500.
- `users.controller.ts:76` — `role` bukan enum (`as any`) → 500 untuk string asing.
- `loan.service.ts:80` — `items?status` string bebas → `as any` → 500.
- NIM duplikat di `users.create`/import: P2002 tidak ditangani → 500 (import
  memakai `skipDuplicates` tapi response tetap mencampur).
Filter error sudah menyembunyikan detail (bagus), tapi statusnya tidak actionable.

### B-07 — MEDIUM — Index kurang pada jalur panas + N+1
- `prisma/schema.prisma`: `Assignment` tanpa index (list/order pakai `deadline`);
  `Submission` hanya unique `[assignmentId, userId]` (query `where: {userId}`);
  `Meeting` hanya `status`/`attendanceCloseAt` (list order `startAt`, calendar range);
  `AbsenceRequest` index `[userId, meetingId]` tidak melayani filter `meetingId` saja;
  `User` hanya `status` (filter `division`/`cohortYear`).
- N+1 per tick: `meetings.service.ts:216-247` (2 query per meeting due + createMany).

### B-08 — MEDIUM — Retensi file tidak lengkap
`apps/api/src/retention/retention.service.ts:22-115` hanya menangani selfie,
lampiran absence, submission, foto loan. Lampiran assignment dan materi **tidak
pernah dihapus**; lampiran absence berstatus PENDING/CANCELLED tidak pernah
tersentuh (filter `reviewedAt: { not: null }`). Bertentangan dengan kontrak retensi
PRD §17 / AGENTS §8.

### B-09 — MEDIUM — 2FA & sesi
- `auth.service.ts:243-248` — `disable2fa` cukup password: sesi yang dicuri +
  password bisa mencabut 2FA tanpa kode TOTP.
- Tidak ada jalur recovery bila authenticator hilang (admin reset password tidak
  menyentuh `totpEnabled/totpSecret`) → lockout permanen.
- Access token tetap valid s/d 15 menit setelah ganti/reset password
  (konsekuensi JWT stateless; desain, bukan bug — tapi perlu dicatat/diputuskan).

### B-10 — MEDIUM — Rate limiting sempit & state tumbuh tanpa batas
`sensitive-throttle.middleware.ts:33-35`: hanya `/auth/*`, POST attendance &
absence-requests. `users/import` (100× bcrypt), export, announcements, baca file
tanpa limit. Map in-memory tidak pernah dibersihkan (kunci lama menumpuk); kunci
per-user diambil dari JWT tanpa verifikasi tanda tangan (didokumentasikan, ember IP
masih berlaku). BFF admin punya ratelimit in-memory sendiri (ceil: 1 replica).

### B-11 — MEDIUM — Audit log bolong di beberapa mutasi
Tidak tercatat: login sukses, logout, refresh, setup/verify 2FA, consent privacy;
`loan.cancel`, `absence.cancel`, `correction.cancel`; `meeting.update` hanya
mencatat status (judul/waktu/lokasi berubah tanpa jejak); `user.update` hanya
role/status. AGENTS §13 menuntut daftar aktivitas PRD §16 diaudit.

### B-12 — MEDIUM — Kunci HMAC fallback ke JWT_SECRET
`apps/api/src/common/jwt-secret.ts:14,18,22` — `FILE_HMAC_SECRET`/`QR_HMAC_SECRET`
kosong = fallback `JWT_SECRET`. Satu kebocoran kunci = bisa forge JWT + link file + QR
sekaligus. `.env.example` menyebutnya "opsional", jadi ini pilihan desain; untuk
produksi sebaiknya diwajibkan (atau alasannya ditulis di DECISIONS).

### B-13 — MEDIUM — Test: cakupan logika berisiko nol
15 file spec unit (28 `it()`) semuanya rules/helper murni; **tidak ada** service test
untuk users, assignments, loans, absence.decide, retention, storage, notifications,
audit, materials, duty. 22 e2e tidak memuat middleware throttle/CORS/headers
(`main.ts` bootstrap tidak dicerminkan di `test/*.e2e-spec.ts`), jadi bug kelas B-01
dan B-10 tidak akan tertangkap. Tidak ada coverage threshold.

### B-14 — MEDIUM — Klaster UX/ops mobile
- Error mentah `e.toString()` ditampilkan ke user (`absence_page.dart:39,45`,
  `notif_page.dart:32`, `profile_page.dart:39`, `meetings_page.dart:68`).
- Kode enum Inggris mentah tampil di UI (reason `SICK`/`ACADEMIC` di dialog absence,
  `absence_page.dart:9-10,269`; status pinjaman).
- Font via `google_fonts` di-fetch runtime — first run offline = fallback font
  (bundle font lebih aman untuk app lapangan).
- Tab `home_shell.dart` di-rebuild tiap ganti tab → state halaman reset.
- Tap notifikasi push selalu push `HomeShell` baru (`main.dart:83-85`) → stack bisa menumpuk;
  tap notif in-app hanya mark-read, tidak deep-link.
- Android release masih ditandatangani debug key (TODO di `build.gradle.kts`);
  URL dev `http://10.0.2.2:3000` butuh network security config untuk device fisik
  (emulator aman).
