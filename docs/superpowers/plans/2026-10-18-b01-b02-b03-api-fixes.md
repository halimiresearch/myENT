## Ringkasan akar masalah (terverifikasi)

### B-02: konstanta `60_1000` (harusnya `60_000`) di 3 tempat
- `apps/api/src/auth/auth.service.ts:84` - challenge 2FA: `Date.now() + 5 * 60_1000` = ~50 menit (komentar `:81` bilang 5 menit).
- `apps/api/src/meetings/meetings.service.ts:177` - token QR: `Date.now() + 5 * 60_1000` = ~50 menit (komentar `:173` bilang 5 menit).
- `apps/api/src/meetings/meetings.service.ts:262` - window reminder penutupan: `now + 30 * 60_1000` = ~5 jam (niat 30 menit).
- Grep repo: hanya 3 kemunculan `60_1000` (ketiga titik ini). Setelah fix harus 0.

### B-03: jam piket diinterpretasi UTC, PRD bilang WIB
- `apps/api/src/duty/duty.service.ts:14-19` `at()` memakai `setUTCHours(h, ...)`: default `open='06:00'`/`close='22:00'` (`:35-36`) menjadi 13:00/05:00 WIB, bukan 06:00/22:00.
- PRD `docs/PRD.md:150-151`: input waktu pengurus diinterpretasikan WIB (Asia/Jakarta) dan dikonversi di backend.
- Tidak ada validasi `open < close`; pasangan terbalik menabrak CHECK `meetings_window_chk` (`prisma/migrations/20261005095900_m1_checks/migration.sql:3`) menjadi 500.
- Form admin tidak mengirim openTime/closeTime, jadi jalur default yang paling terdampak.

### B-01: 4 lubang scope divisi (AGENTS §6 + `common/policy.ts`)
1. `assignments.service.ts:149-160` - `review(actorId, id, note)` tanpa scope; pembanding `fileUrl` (`:162-172`) sudah pakai `canManageMember`. Controller (`assignments.controller.ts:64-68`) mengizinkan OFFICER dan ADMIN.
2. `users.controller.ts:193-199` - import CSV menulis `division: r.division` dari file; pembanding `create` (`:68`) memaksa officer ke divisi aktor.
3. `attendance.service.ts:115` - `adjust`: `actor.id !== target.id && !canManageMember(...)` membuat self-adjust selalu lolos (semua role); pembanding `absence.decide:112` dan `correction.decide:100` melarang keputusan untuk diri sendiri.
4. `loans/loan.service.ts:121-149` - `returnLoan(actorId, ...)` tanpa scope; controller (`loan.controller.ts:93-103`) hanya OFFICER/ADMIN; pembanding `loan.list` (`:177-179`) pakai `divisionScope(actor, 'borrower')` dan `photoUrl` (`:200`) pakai `canManageMember`.

Konfirmasi pendukung: `req.user` diisi JwtAuthGuard (`common/jwt-auth.guard.ts:19-24`) dengan `{ id, nim, name, role, status, division, cohortYear, mustChangePassword }`, jadi object actor selalu tersedia di controller.
